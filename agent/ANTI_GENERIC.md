# Anti-Generic UI Rules

The objective is not to ban common patterns. It is to ban unmotivated patterns.

## Red flags

Treat these as suspicious unless the project DNA explicitly justifies them:

- centered SaaS hero with eyebrow, gradient headline and two CTAs;
- excessive rounded cards floating on a neutral background;
- purple/blue gradients used as a default "tech" signal;
- glassmorphism without a product reason;
- bento grids used because they are fashionable rather than informative;
- generic icon + heading + paragraph feature grids;
- every section constrained to the same centered max-width rhythm;
- multiple unrelated border-radius values;
- excessive pills/badges;
- random blobs, glows or grid backgrounds;
- fake dashboard screenshots or meaningless analytics cards;
- stock "AI sparkles" iconography;
- every block separated by equal vertical spacing;
- identical hover animation on every interactive element;
- excessive use of gradients to create hierarchy instead of typography/composition.

## Replacement behavior

Before adding a pattern, answer:

1. What user or brand problem does this solve?
2. Why is this composition appropriate to this industry and audience?
3. Is there a simpler structural solution?
4. Does it duplicate a visual device already overused elsewhere on the page?
5. Would this exact section look plausible if pasted into an unrelated AI startup website?

If the answer to #5 is yes, redesign it unless the project's identity genuinely calls for that convention.
