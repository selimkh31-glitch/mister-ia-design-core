# Design Protocol

## Phase 1 — Define

Create the project design system before page implementation.

Required outputs:

- audience and positioning;
- 3–6 brand attributes;
- visual archetype;
- photography/illustration direction;
- typography strategy;
- color roles;
- spacing rhythm;
- radius philosophy;
- motion philosophy;
- density level;
- explicit anti-patterns.

## Phase 2 — Tokenize

Convert visual decisions into semantic tokens.

Prefer roles such as:

- `--color-brand-primary`
- `--color-surface-canvas`
- `--color-surface-raised`
- `--color-text-primary`
- `--color-text-muted`
- `--space-section-y`
- `--radius-control`
- `--shadow-raised`
- `--motion-enter`

Do not encode one-off component names into foundational tokens unless they represent a stable semantic role.

## Phase 3 — Compose

Use reusable primitives as raw material. Adapt composition, typography, imagery and spatial behavior to the project DNA.

## Phase 4 — Review

Check visual identity before micro-polish. If the page could be mistaken for another project, stop and correct direction before adding more components.

## Phase 5 — Validate

Run design lint, inspect responsive behavior and complete the project QA checklist.
